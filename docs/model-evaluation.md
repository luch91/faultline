# Model evaluation status

Prior controlled local calls showed that Meta Muse Spark extracted a validated workflow and that Spark and Muse Wonder each performed a bounded two-turn investigation against the Missing Approval fixture. A separate authenticated Baseten call to the Meta Muse Spark Open model returned candidate interventions for deterministic validation. These observations establish connectivity and tool integration for those individual calls.

No twelve-case live model comparison has been run. The deterministic Minsk Failure Benchmark does not call any model and cannot establish model extraction accuracy, relative model quality, latency distributions, or model-assisted detection improvement. Public preview inference remains disabled. No new model calls were made for this branch.

`pnpm model:evaluate` prints an offline plan and verifies that the existing Missing Approval and held-out workflows route to Spark and Wonder respectively. It makes no provider request. The optional `--live` mode targets only a local protected Worker and requires an explicit authorization flag, a $0.30 evaluation limit flag, `MINSK_EVAL_TOKEN`, enabled budgeted endpoints, and the Baseten test token. The local Worker must receive the same `MINSK_EVAL_TOKEN` as a private environment variable. Its planned six provider calls are one Spark extraction, two Spark investigation calls, two Wonder investigation calls, and one Baseten challenger call. Every Meta or Baseten reservation carrying the protected evaluation token shares one Durable Object session with a six-dispatch and $0.30 conservative estimate limit. Retries and fallback consume new slots. This is an application dispatch guard, not a provider-side billing guarantee; actual usage can exceed estimates and must be reconciled. The plan records schema and evidence checks, actual tool outcomes, latency, and ledger deltas. Direct model-only analysis is not exposed by the current budgeted API and is marked unsupported rather than simulated.

The existing $100 internal Meta ceiling and provider-specific budget controls remain in the Worker. Previous Meta Billing reconciliation used a rounded $0.04 credit change against a $0.033150 local estimate for five calls. The current credit balance and Baseten credit balance have not been independently read during this branch's validation. The previous five-call authorization is exhausted. The six-call evaluation plan needs new explicit authorization and current billing evidence before running.

The evaluation ledger now accepts private Worker settings `MINSK_EVAL_MAX_CALLS` and `MINSK_EVAL_MAX_MICRO_USD`, capped at 100 dispatches and $10 of conservative estimates. Without those settings, the original six-call and $0.30 limits remain in force. These settings must only be added to a protected local Worker after authorization. The current harness still executes only its four-task pilot; a larger comparative dataset and scorer have not been implemented or run. Do not treat the configurable ceiling as authorization to spend it.
