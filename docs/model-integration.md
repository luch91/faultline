# Model integration

Muse Spark 1.3 performs extraction and routine investigations through Meta Responses. Muse Wonder 1.0 is selected for complex workflows when enabled. Baseten serves the Meta Muse Spark Open challenger as `meta-models/muse-spark-open-1026`. Model-proposed interventions are validated against the workflow and the deterministic simulator decides outcomes.

Meta requests require `MODEL_CALLS_ENABLED=true`, `META_CREDITS_CONFIRMED=true`, `META_BILLING_MODE=Standard` and a server-side `MODEL_API_KEY`. Wonder also requires `WONDER_ENABLED=true`. Baseten requires its key, `BASETEN_CHALLENGER_ENABLED=true`, `BASETEN_CREDITS_CONFIRMED=true`, and a positive `BASETEN_CEILING_MICRO_USD`. The protected challenger route requires `BASETEN_TEST_TOKEN` unless the separate `PUBLIC_CHALLENGER_ENABLED` switch is explicitly enabled. All switches default to disabled. Store secrets outside Git.

The SQLite-backed Durable Object reserves before each provider call and tracks provider-reported token usage separately. Missing usage and failures retain the reservation. Meta uses a default $50 cumulative ceiling, configurable downward through `META_CEILING_MICRO_USD`. Baseten has no hardcoded dollar ceiling; it fails closed until configured. These estimates are not provider billing limits. Compare rates with [Meta pricing](https://dev.meta.ai/docs/pricing-rate-limits) and [Baseten pricing](https://www.baseten.co/pricing/) before activation. Rate limits, maximum outputs and timeouts bound individual calls.

The controlled benchmark Worker uses `MINSK_EVAL_TOKEN`, `MINSK_EVAL_MAX_CALLS` and `MINSK_EVAL_MAX_MICRO_USD`. Run `pnpm benchmark:models -- --provider meta`, `baseten`, or `all` with `MINSK_EVAL_API_URL` and `MINSK_EVAL_TOKEN` in the CLI environment. Baseten also requires `MINSK_EVAL_TEST_TOKEN`. Point the CLI at localhost for BYOK or an explicitly authorized HTTPS Worker. Configure provider keys on that Worker, never in a browser. Results are written to ignored `model-evaluation/results/` and contain synthetic workflow data and actual model output.

See [the local live smoke evidence](issue8-live-smoke.md) for actual provider results, [the historical model evaluation](model-evaluation.md) for the prior experiment, and [security](security.md) for deployment controls. A small synthetic sample does not establish real-world reliability. Certificate integrity verifies consistency and does not authenticate the issuer.
